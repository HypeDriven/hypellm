    The HypeLLM reference job shim

    job-shim/ holds the reference job shim: a small HTTP server that stands beside one generative service and speaks the router's job protocol on its behalf (orchestration §11.3). It serves the protocol for any service that can be run as a command — one verb, one argv, a declared set of output files — and it is the behaviour a service-specific shim is measured against. It is not part of the Cargo workspace.

    Status. Built and tested by its own suite, and checked once against the router binary end to end. No shim for a particular service — TRELLIS, FLUX, YuE, H3, Kimodo — is built; each needs its own argv and, where the service is not a command, its own backend (§11.4).

    Why it is a separate process

    Running a generator is executing a process, which the router never does (router specification §26.2). Putting the variable part out of process, behind a narrow protocol the router owns, is the answer the router already gives three times — the identity verifier, the TLS helper and the fleet agent. To the router a shim is a provider like any other: an administrator-configured destination, untrusted, read with bounded parsers.

    What it keeps

    • The router authenticates, every request. A bearer token from a key file the shim refuses to read if group or others can, compared in constant time. Nothing, not even health, answers without it. Put the service where only the shim can reach it.
    • Inputs are bytes, never references. An input is a name, a media type from the protocol's closed set, and base64 data. A body with a URL, a path, or any field it does not know is refused, and nothing runs. Inputs are written into the job's own directory, as in/<name>.<ext>, and the command runs in that directory.
    • No shell. A verb's argv is an absolute program and fixed arguments; {prompt}, {input:<name>}, {params_file}, {options_file} and {out_dir} are replaced by whole values. A prompt is one argument, literally.
    • Outputs are declared. After the command exits 0, each declared output must be a regular file — not a link — inside the job's output directory and within max_part_bytes. Anything else fails the job, and nothing undeclared is served.
    • Closed vocabularies. A command signals invalid_input by exiting 65 and out_of_memory by exiting 75; any other failure is internal. The router waits and retries on out_of_memory and fails the job on the rest.
    • Bounded. Request bodies, inputs (four), connections, one job running at a time — a second submit is 503 not_ready — a job's wall time, 64 retained jobs, and part sizes. A failed or cancelled job's files are removed at once, a succeeded one's after retention_s, and everything a previous process left is removed at start.
    • No prompt is logged. A log line is the method, the route and the status.

    The protocol

    GET    /job/v1/health                 → 200 { verbs[] }
POST   /job/v1/jobs                   → 202 { id }
GET    /job/v1/jobs/{id}              → { state, progress_permille, elapsed_ms, error, parts[] }
GET    /job/v1/jobs/{id}/parts/{name} → bytes, with Content-Type and Content-Length
DELETE /job/v1/jobs/{id}              → 202 { stopped }

    The router's side is hypellm_adapters::job. A cancel stops the command's whole process session and reports stopped: true; the router holds the job's slot until the next status says cancelled. Progress is whatever the command writes, as an integer in permille, to the verb's progress_file in its output directory; without one it is 0 until the job finishes.

    Configuration

    A JSON file; job-shim/job-shim.example.json is a TRELLIS-shaped example. Unknown fields are refused, so is a relative program, a placeholder the shim does not know, an {input:…} the verb does not declare, an output file name with a separator, and a media type outside the protocol's set. An optional input has no placeholder — there is no whole value to put in its place when it is absent — so naming one in argv is refused too; the command finds it at in/<name>.<ext>, or does not.

    Field Meaning Default
    listenhost:portrequired
    key_fileThe bearer the router presents: 16–4096 visible ASCII characters, mode 0600required
    work_dirAbsolute; one directory per job beneath itrequired
    verbsVerb name to argv, inputs (name to media types, or to {"media_types": […], "optional": true}), parts (name to file, media_type, optional), timeout_s, progress_filerequired
    max_body_bytesLargest submit body64 MiB
    max_part_bytesLargest output served1 GiB
    max_connectionsConcurrent connections; past it a connection is closed16
    retention_sHow long a finished job is kept900

    Setting it up

    1. Write a key: head -c 32 /dev/urandom | base64 > /run/secrets/hypellm-job-shim.key, mode 0600. Put the same text in the router's <secrets>/credentials/<credential-id>.
    2. Write the configuration and start it: job-shim/hypellm-job-shim --config job-shim.json.
    3. Declare it to the router as a family=job provider with that credential, a target with operations=job and the verb in capabilities, and an alias declaring the same capability — see Deployment & configuration.

    Backends

    A service that is not a command is reached through a backend: a command, in job-shim/backends/, that turns one job into one call to the service and its answer into the declared files. Each is Python's standard library only; each takes the service's address from a fixed --service argument in the configuration, never from the job; each refuses a param or option it cannot honour (exit 65) rather than ignoring it; each checks that what the service returned is the media type the part declares.

    Backend Verb Service Takes Writes
    flux.pytext-to-imageFLUX.2 [klein] HTTP API, POST /generateprompt; width, height (multiples of 16, ≤ 1536), steps (≤ 60), seed, count (≤ 4); option guidance_scale; optional input reference (an edit)image.png … image-4.png
    trellis.pyimage-to-3dTRELLIS HTTP API, POST /generateinput image, no prompt; seed, steps; options formats, remove_background, guidance strengths, simplify, texture_sizemesh.glb, and geometry.ply / gaussians.ply
    comfy_yue.pytext-to-musicComfyUI with YuE2: a fixed graph, POST /prompt, /history, /viewprompt (the style); duration_ms (≤ 6 min), seed, steps; option lyricsaudio.flac
    gradio_h3.pyaudio-to-videoMiniMax-H3 Gradio app, and its prompt conditionerprompt; input audio, optional keyframe; duration_ms (2–6 s at 1080p), steps, seed; option resolutionvideo.mp4
    kimodo.pytext-to-motionKimodo's text encoder; the motion model runs in the shim's containerprompt; duration_ms (≤ 10 s per sentence), seed, steps; options bvh, postprocessmotion.npz, motion.bvh

    Nothing a caller sends becomes a URL, a path, a node, a file name or a model name on the service's side. FLUX's and TRELLIS's own APIs accept a path inside their container where an image goes; the backends only ever send bytes. The YuE2 graph is fixed in comfy_yue.py, with the caller's style and lyrics as values in it. A reply naming a file outside the service's /outputs/, or audio saved anywhere but the job's own prefix, fails the job instead of being fetched, and no backend follows a redirect.

    A cancel stops the backend's session. comfy_yue.py also takes its prompt out of ComfyUI's queue, or interrupts it by its own id when it is the one running — never a bare /interrupt, which would stop another client's work. The others cannot stop work a service has already started: see below.

    Checking it works

    python3 job-shim/test_job_shim.py runs its suite against a generator script it writes per run: no network beyond loopback, no service, no GPU. It covers the key on every route, inputs as bytes only, no shell, declared outputs only (a link, a missing file and an oversized one each fail the job), the exit-code mapping, one job at a time, a cancel stopping the command and removing its files, paths that are not identifiers, bounded and unambiguous bodies, optional inputs, and configuration refusals. Run it when touching job-shim/.

    python3 job-shim/backends/test_backends.py runs each backend the way the shim does, against fake services on loopback that record what they are sent: that a param or option the service cannot honour sends nothing, that each service status lands on the right exit code, that a reply naming a file elsewhere is not fetched and a redirect is not followed, that a ComfyUI cancel removes only its own prompt, that H3's conditioning is written under the app's cache key and reused, and that Kimodo's prompt stays one argument in an environment the backend builds rather than inherits.

    What it does not do

    • It runs one job at a time and queues nothing; the router's job queue does the waiting.
    • A backend cannot stop what a service has already started, except ComfyUI's. A cancelled FLUX, TRELLIS or H3 job still finishes rendering on the service — the service holds its GPU until then — and its result is discarded.
    • The services' own outputs are not cleaned up: FLUX's and TRELLIS's /outputs, ComfyUI's hypellm/ folder and H3's render directory keep every file a job made.
    • It does not make the service private. The bearer protects the shim; a service still listening on the network can be called around it.
    • It does not isolate the command beyond a private working directory, a minimal environment and its own process session. Run it as an unprivileged user, in the service's container.
    • Its jobs are not durable: a restart forgets them and removes their files.
